# Frontend Integration Guide (For Member 1 & Antigravity IDE)

Hi Member 1! 👋 
Member 3 has completed the frontend UI for FinTrack (Tasks 15-19, plus scaffolding for Part B pages). The frontend is currently a static React application built with Vite and Tailwind CSS. 

Since you are also using Antigravity IDE, you can point your agent to this file to quickly understand how the frontend is structured and what needs to be wired up to your backend APIs to make the application "alive".

## 1. Tech Stack & Environment
- **Framework:** React + Vite
- **Styling:** Tailwind CSS (v3.4.x) — *Note: We specifically downgraded to v3.4 because the Google Stitch UI configuration was incompatible with Vite's default Tailwind v4. Please do not upgrade Tailwind or modify `tailwind.config.js` unless necessary, as it might break the layouts.*
- **Routing:** React Router v6
- **Location:** The entire frontend lives in the `frontend/` directory. 

## 2. Routing Structure
The routes are defined in `frontend/src/App.jsx`. All internal links between sidebars have already been wired to point to these routes.
- `/login` -> `Login.jsx`
- `/dashboard` -> `Dashboard.jsx`
- `/transactions` -> `Transactions.jsx`
- `/upload` -> `Upload.jsx`
- `/budgets` -> `Budgets.jsx`
- `/insights` -> `Insights.jsx`
- `/report` -> `Report.jsx`

## 3. Integration Checklist (How to make it "alive")

Currently, all the data you see in the UI (transactions, balances, charts, AI queries) is **hardcoded static JSX**. To integrate your backend, your Antigravity agent should perform the following steps for each page:

### A. API Setup
- Create an API service file (e.g., `frontend/src/api/client.js`) using Axios or Fetch to define the base URL and handle JWT tokens (from your Auth module - Task 7).

### B. Page-by-Page Integration Requirements

**1. `Login.jsx`**
- **Current State:** The form intercepts the submit event and blindly navigates to `/dashboard`.
- **To-Do:** Wire the form to your `/api/auth/login` endpoint. Store the returned JWT token (localStorage/context) and handle error states (e.g., invalid credentials).

**2. `Dashboard.jsx`**
- **Current State:** Balances, recent transactions, and SVG sparklines are hardcoded.
- **To-Do:** Fetch user summary data. Replace the static SVG sparklines with `Chart.js` components (Task 19) driven by backend data.

**3. `Transactions.jsx`**
- **Current State:** The table rows are hardcoded HTML.
- **To-Do:** Fetch from your Transactions list/search route (Task 13). Replace the static table rows with `transactions.map(...)`. Wire up the search bar and filter dropdowns to send query parameters to your API.

**4. `Upload.jsx`**
- **Current State:** The drag-and-drop zone is a static visual representation. 
- **To-Do:** Connect the file input to your parsing service upload route (Task 9). Add a loading state while your backend processes the CSV and categorizes merchants.

**5. `Insights.jsx` (AI Feature)**
- **Current State:** The "Ask FinTrack" search bar is static, and the query result/forecast cards below it are hardcoded.
- **To-Do:** When the user hits "Execute", send the query to your NL-to-SQL pipeline. Display a loading spinner, then replace the static result card with the dynamic SQL output and metrics. 

**6. `Budgets.jsx` & `Report.jsx`**
- **Current State:** Static UI.
- **To-Do:** Wire up CRUD operations for budgets (Task 12) and connect the "Export" buttons to download actual PDFs/CSVs generated by your backend.

## 4. Notes for your Antigravity Agent
If you ask your agent to "Wire up the Transactions page to the API", tell it to:
1. Look at `Transactions.jsx` to find the repeated table row `<tr>` pattern.
2. Isolate the row into a map function.
3. Use `useEffect` (or React Query) to fetch the data on mount.
4. It is completely safe to strip out the static placeholder HTML as long as the Tailwind classes on the parent containers are preserved.

Good luck with the integrations! Let Mem 3 know if any UI components need adjusting based on the real API data shapes.
